# helper_fx2/sdboot: the FX2 1.01 start-up loader, build `fx2boot_v1`

Read `SDBOOT.md` first (what it is, how to try it, how to undo it). Not run on a camera.

| File | What |
|---|---|
| `fx2hook.c` | The start-up hook named in `/etc/ld.so.preload`. No imports. |
| `fx2boot.sh` | The helper the hook starts once per power-on: runs the plan's step libraries with the camera's shell. |
| `fx2cp.c` | `dmm_alloc`, `dmm_free`, `sen_dma_transfer` for a process outside the camera application (soname `libsencore.so`). |
| `fx2boot_mp_gen.c` | Generated: `helper/readcheck.c` with the eight text changes of `MP_EDITS` (levels 18 to 20 from outside the application). |
| `fx2boot_read_out_gen.c` | Generated: `helper_fx2/fx2read.c` with the six text changes of `OUT_EDITS` (the read-only check from outside the application, X21: it reads the camera application's maps and memory, issue #16). |
| `fx2boot_put.c` | A kit step that brings one piece of one loader file to the camera's RAM disk (W1 to W14). |
| `fx2boot_ctl.c` | The kit steps W30 (run now), W40 (install), W41 (uninstall), W42 (status), W50 to W53 (plan), W58 / W59 (off switch). |
| `fx2boot_sys.h`, `fx2boot_out.h` | System calls, SHA-256, the kit's result-file frame. |
| `fx2boot_manifest.h`, `fx2boot_hookfile.h`, `fx2boot_pins.json` | Generated by the build: sizes and SHA-256 of every file. |
| `build_fx2boot.py` | Builds everything with the kit's compiler and flags; checks imports, sonames and sizes. |
| `update_runner.py`, `pins_for_runner.py` | Write the pins into `fx2_run.py`; check that runner, pins file and files agree. |
| `libJit_fx2_*.so`, `fx2cp.so`, `fx2hook.so` | The builds. `L13`, `H5`, `P5`, `L5`, `L16`, `S16` are copies of the kit's pinned files; `X18`-`X21` are built here for a process of their own. |
| `emu/prepare_emu.py`, `emu/emu_fx2boot.py` | The offline test under the camera's own loader and shell (WSL, qemu-aarch64): 78 checks. |
| `emu/emu_fx2cp_diff.py` | `fx2cp.so` against the camera's `libsencore.so`, call by call (Unicorn): 9 cases. |
| `emu/emu_fx2read_out.py`, `emu/dump_tables.c` | Offline test of X21 alone (Unicorn, no firmware, no camera): the kit's check inside the camera application vs. X21 outside it. It reproduces issue #16 (all six `libmpr` sites `NOT MAPPED` from outside) and shows X21 reading them STOCK, TARGET, and refusing when there is no camera application or two. 6 cases. Needs `unicorn` and a host C compiler for `dump_tables.c`. |
| `emu/model_osal.c`, `emu/model_kernel.c`, `emu/fake_im.py`, `emu/debug_shell.sh` | Stand-ins and tools of the test. Never sent to a camera. |
| `emu/RESULT_emu_fx2boot.txt`, `emu/RESULT_emu_fx2cp_diff.txt` | The two tests' output for this build (2026-11-28): every check with its outcome. |

Rebuild and test (from the map; the firmware files and the compiler are not in the published kit):

```text
C:\Python313\python.exe -B build_fx2boot.py
C:\Python313\python.exe -B update_runner.py
C:\Python313\python.exe -B pins_for_runner.py --check
C:\Python313\python.exe -B emu\prepare_emu.py
wsl.exe -e python3 "/mnt/c/.../helper_fx2/sdboot/emu/emu_fx2boot.py"
python3 -B emu/emu_fx2read_out.py
C:\Python313\python.exe -B emu\emu_fx2cp_diff.py
```

`ZIG_CC` overrides the compiler (the default is the author's venv under the map); `python3 -m ziglang cc` from zig 0.13.0 gives the
same bytes. `build_fx2boot.py` builds `fx2cp.so` from the firmware's own libraries, which are not in the published kit: with no
firmware tree, keep the published `fx2cp.so` and build only the rest (`--regen` also regenerates the two generated sources).
